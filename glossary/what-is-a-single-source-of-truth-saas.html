What is a single source of truth in SaaS

A single source of truth is the place where a company's key definitions live, starting with the ones teams tend to read differently: what counts as an active user, when a lead becomes an MQL, whether a larger renewal is an upsell. It also names the reference system for each figure. It doesn't mean every team sees one number. It means that when two numbers differ, anyone can see why.

Why the phrase comes up so often

Most SaaS companies end up with product usage in one tool, CRM activity in another and billing somewhere else. Each tool tells part of the story. Marketing looks at sign-ups and feature usage, sales at deal stages and account value. When the figures don't line up, the conversation shifts from "what should we do?" to "whose number is right?". A shared dashboard helps, but it doesn't settle the question on its own if the definitions behind it are still unclear.

One source of definitions, not one number

Two teams can work from the same definitions and still report different figures, both correct. Sales reads the pipeline deal by deal, while marketing reads it through an attribution model that splits each deal across the touches that came before it. They answer different questions (see why marketing and sales pipeline numbers don't match).

Counting can do the same. Say a team counts trial sign-ups once per account and per month, because ten people from the same company starting a trial still lead to one purchase, not ten. The definition is sound. But an account that signs up in two different weeks counts once in each weekly total and once in the monthly one, so the four weeks add up to more than the month. The CRM, which records each person, shows a third figure. All three are right.

Signs the definitions aren't shared

  • Meetings start by reconciling numbers instead of discussing them.
  • One team's "active user" is another team's "logged in once last month".
  • Sales signed off on the criteria that make a lead an MQL, yet still questions the quality of the leads it receives, or asks for more of them.
  • A customer renews with more seats, and one team books it as an upsell while another books it as a renewal.
  • A definition changed, and nobody knows when, so this quarter is compared with last quarter across the break.

How to start without overengineering it

Write down the definitions of the few metrics that drive decisions, and name the reference system for each one. Start with the two or three sources that cause the most disagreement, usually product usage and CRM data. A spreadsheet is enough to check which fields actually matter. Log every change to a definition with its date and reason. What matters at this stage is agreement, not speed: the people who own activation, retention and revenue reporting need to sign off on what each metric means before it gets automated.

Is a single source of truth the same as a data warehouse?

Not necessarily. A data warehouse is infrastructure for storing data. A single source of truth is an outcome: everyone reading figures built on the same definitions. You can reach it with a warehouse, or with a simpler shared tool, depending on team size and complexity.

Should every team see the same number?

No. Every team should read figures built from the same definitions, but the figures can differ because they answer different questions: a deal-by-deal pipeline for sales, a split by channel for marketing, a summary for leadership. What matters is that each figure says which rule it follows, and that totals come from the reference system.

Do we need to unify every data source at once?

No. Start with the two or three sources that cause the most disagreement, usually product usage and CRM data, and expand from there once the definitions are settled.
