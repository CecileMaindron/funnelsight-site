Start tracking your PLG funnel

A first funnel view takes two exports and one definition your team agrees on. With access to the right data, it can be ready the same day.

A first view, built in an afternoon

A growth marketer exports last month's sign-ups from the CRM, with the source of each one, and a usage export from the product. The team has agreed that a user is activated once they share a first project with a teammate within 14 days. Both files go into Funnelsight as a spreadsheet and are matched on each user's email. When the usage export has no email, which is common for privacy reasons, the match runs on the user ID the product assigns, as long as the CRM stores it too. Sign-ups with no recorded source stay in the view, labelled as such, rather than disappearing. The view below is ready before the end of the afternoon.

Paid search brings more sign-ups than referrals, yet fewer of its users activate: 60 against 90. Ad platforms learn to find the people most likely to sign up, who aren't always the ones who go on to use the product. A report that stops at sign-ups would send more of next month's budget to paid search. Referrals, where half the users activate, would get none of the attention. The same usage export, taken again a few weeks later, shows whether those activated users stay. The funnel metrics cheat sheet lists what to add next, and how long each metric takes to read.

Where each step's data lives

Each step of the funnel, and where its data comes from

  1. VisitCampaign tags on each link, saved with the sign-up
  2. Sign-upThe CRM or the sign-up database, with each user's source
  3. ActivationYour decisionA usage export, read against the event your team chose
  4. Still activeThe same usage export, a few weeks later
  5. PayingBilling, or the CRM

Activation is the one step you can't export. It's a decision, and the one most likely to cause arguments later, so it's worth settling first. What counts as activation in PLG walks through how to choose it.

No product analytics tool yet?

A product analytics tool isn't a prerequisite, and it comes with its own work. Someone has to instrument the product so it sends clean events, and depending on the country, users may have to consent before they're tracked. Until then, other signals can stand in for usage.

  • The product's own database, which already records what accounts create, connect or configure.
  • Light tracking on the web app, when the product runs online.
  • Requests that can only come from inside the product, such as a form that only appears after a few days of use. When one arrives, it confirms the user got that far.
  • A thank-you page after a download, where a visit confirms the download started and a short form can tell you who it was.

What you can do alone, and where you'll need help

You can start alone, but the data belongs to several teams and comes with rules, so part of the work needs someone else.

You can do yourself

  • Lay out the funnel steps and propose an activation event
  • Import the exports and check how they match
  • Read the view and compare sources
  • List what the view can't see yet

You'll need someone else for

  • Access to the CRM and product exports, often granted by an admin
  • Knowing which fields to export, such as the user ID the product assigns, and what each one means
  • Agreement on the activation event from the teams that use it
  • Recording an event the product doesn't capture yet
  • The data rules: an export holds personal data, so keep only the columns you need, store it where access is limited, and delete it once imported

From a first view to a weekly one

You could get a similar first view from a spreadsheet or a one-off import. It stops being enough once several teams report on the same funnel every week, and a few signs point to that moment:

  • Someone spends a morning every week rebuilding the same view.
  • Two people get two different activation numbers from the same file.
  • A column moved and broke the formulas, and nobody noticed until a meeting.
  • Leadership asks for a trend, and the history only goes back to the last rebuild.

A dedicated tool doesn't fix the data it receives. Campaigns still need consistent tags, and the activation event still needs the teams' agreement. What changes is that those rules are written once and applied to every report, and that a live connection replaces the manual re-import.
